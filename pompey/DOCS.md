# Home Assistant Supervisor notes

Delivery receipts in `/data/pompey/state/deliveries.json` persist successful final-library imports by external movie/series identity and episode coordinates. The existing locked download job records evidence before disabling movie or individual-episode monitoring. Later user file moves/deletions do not reopen delivery. Native final-library import history can backfill earlier success; staging history cannot. Explicit release rejection reopens affected receipts before native changes, excludes the rejected file from satisfying that retry, and re-enables its monitoring for replacement. These receipts never authorize file/torrent deletion and are not a live Plex inventory. Seerr retains media-server discovery. Native libraries and in-flight downloads remain visible separately.

Supervisor builds `pompey/Dockerfile` locally for amd64 and starts one container. Users do not need to run Docker and Pompey publishes no image. Supervisor supplies `/data/options.json`, persistent `/data`, `/config` and `/media`.

The image contains all pinned applications in `/opt/pompey/engines` and Recyclarr resources in `/opt/pompey/resources`. Startup never fetches engines. Applications and controller jobs run as root inside the container for compatibility with Supervisor-managed SMB/CIFS mounts. Container isolation and the Home Assistant AppArmor profile provide containment; applications share a trust boundary. No dedicated application user or ownership rewrite is required. Startup checks real storage operations and preserves existing ownership. Server-side permissions and read-only mounts still apply.

s6 runs cont-init scripts before services. Initialization installs the atomic fail-closed firewall, generates configuration and creates mutable paths before engines start. Local applications do not wait for a working tunnel. WireGuard setup and firewall maintenance remain privileged. Only the short-lived endpoint DNS resolver uses the existing nobody identity (UID/GID 65534), restricting the bootstrap DNS exception to its sockets; applications retain VPN DNS and cannot use LAN DNS when the tunnel is down. Private networks directly connected to the container are detected automatically, including local HAOS services. Additional LAN exceptions come from `lan_networks`. Dedicated TCP source-port routing keeps published-interface replies on the original container interface; the firewall still rejects new unapproved outbound connections, even with a published source port. DNS filtering precedes both automatic and explicit local-network exceptions.

Ingress on port 8099 provides setup, live status and diagnostics. Seerr is published on 5055 and Prowlarr on 9696. Internal application interfaces are always available through authenticated Ingress; the former debug option is no longer used. Diagnostics are available independently; explicit searches contact sources and show real Arr decisions. Media servers are optional and separate. The overview reports active torrents, monitored titles, enabled-source availability and open requests from a shared read-only observation cache. Failed application reads retain timestamped last known values. The Releases table explains native Arr queues, missing monitored media and torrents outside Arr queues. Title search and an attention filter narrow the list; a single expanded detail stays directly beneath its item. Native download identities keep same-series transfers distinct across refreshes. Releases includes Try another for active and imported releases, with an exact native-file preview before confirmation. Native Arr owns deletion, blocklisting and replacement selection; the action explicitly submits a search because normal failed-download auto-retry is disabled. Its durable journal records intent before mutation and preserves partial failures without replaying them. Imported season packs list all linked current episode files. Release-sequence diagnostics can be copied or saved beside the workflow; general logs remain in HA Logs. The journal is bounded to 50 sequences, 20 attempts and 200 native events per sequence; imported outcomes are pruned first. Open sequences are observed for 30 days, with limits and collection failures disclosed in the export. Explicit Inspect releases actions contact sources without grabbing releases. Contextual connection checks replace the Setup tab; bundled application versions and native interface links are on Config. Overview metrics link to the matching applications. Individual indexer retry details remain inside their metric. The refresh countdown changes to a warning when updates fail. Recovery shows at most five recent entries with Diagnostics alongside; full retained evidence remains in the export. Review import links blocked imports to the managing application’s Activity → Queue page for native interactive import; no automatic file remapping or forced replacement is added. Healthy maintenance timestamps are omitted from the interface; maintenance failures remain visible through health warnings and HA Logs. Config saves concurrency and dual-audio preferences in `/data/pompey/state/preferences.json` under the stack lock. All policy consumers read these effective preferences, with legacy HA/environment values used until the first save. The configuration job applies live qBittorrent preferences and resynchronizes Recyclarr when the audio preference changes; only a successful complete pass acknowledges them in `preferences-applied.json`. Controller failures leave them visibly pending. Storage warnings remain visible across tabs. Arrow keys, Home and End switch tabs.

The controller serializes mutations. Download maintenance, rating routing, profiles and initialized search connections have their own prerequisites. Before Seerr has its first administrator, its public wizard is available and API-key 403 responses are expected. Afterwards both Arr connections, configured Prowlarr apps and an enabled synchronized source are required. Optional sign-in and interface settings do not override required connection failures.

Cold HA backups stop the add-on for a consistent state copy. There is no runtime bundle updater, database rollback manager or supported migration from the old architecture. Fresh installations remain the primary supported layout. Release acceptance additionally exercises a selected previous stable image with real completed, waiting and partial-download state; arbitrary historical migrations and downgrades remain unsupported. See [testing](../docs/testing.md) for what automated acceptance proves and the remaining hardware boundaries.

## Download and storage safety

qBittorrent excludes executable/script filenames (`exe`, `com`, `scr`, `msi`, `bat`, `cmd`, `ps1`, `vbs`, `js`, `lnk`) with its native case-insensitive file filter. The filter applies after torrent metadata is known and before those files are selected for transfer. Pompey cannot identify every unsafe release from a search title and does not scan media for malware. Mixed wanted/excluded files may share torrent pieces.

After a recovered VPN interface replacement, Pompey gracefully restarts qBittorrent once to reopen bound connections. Native resume data preserves partial bytes and individual stopped torrents; deliberately held services are not restarted.

Startup remembers paths previously observed on network filesystems and refuses a later local-filesystem fallback. During operation, a bounded storage check every fifteen seconds verifies mount identity and write operations. An I/O error or probe timeout suspends Pompey maintenance without terminating native imports. Only a confirmed mount identity change stops qBittorrent, Radarr and Sonarr, limiting writes to an unexpected filesystem while leaving local requests and setup accessible. A later inconclusive probe never releases services held for a confirmed mount change. The dashboard retains the overview and explains the storage interruption. Restored storage releases only the applications Pompey held. Detection is periodic, not an atomic safeguard against every write during a mount outage. Native cleanup interrupted mid-removal can leave files requiring review; Pompey does not guess which unowned files to delete.

Home Assistant Logs retain the first actionable upstream warning/error and summarize equivalent repeats for sixty seconds. Redaction is best effort; review copied logs before posting them publicly. Diagnostic uploads are not automated.

### Native move policy (0.6.3)

Completed managed torrents stop sharing. Saved ratio/day values normalize to stop-sharing without changing other preferences; legacy HA keys remain accepted. The controller resets managed per-torrent share limits to ratio zero and disables duration limits. Arr completed-download removal remains enabled, with hardlinks disabled. Native Arr continues owning imports and upgrades; there is no custom importer or patched dependency. Same-filesystem media renames are preferred, but native copy fallbacks and manual-copy imports remain possible. CIFS behavior depends on the server and mount layout.
