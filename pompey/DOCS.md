# Home Assistant Supervisor notes

Supervisor builds `pompey/Dockerfile` locally for amd64 and starts one container. Users do not need to run Docker and Pompey publishes no image. Supervisor supplies `/data/options.json`, persistent `/data`, `/config` and `/media`.

The image contains all pinned applications in `/opt/pompey/engines` and Recyclarr resources in `/opt/pompey/resources`. Startup never fetches engines. Applications and controller jobs run as root inside the container for compatibility with Supervisor-managed SMB/CIFS mounts. Container isolation and the Home Assistant AppArmor profile provide containment; applications share a trust boundary. No dedicated application user or ownership rewrite is required. Startup checks real storage operations and preserves existing ownership. Server-side permissions and read-only mounts still apply.

s6 runs cont-init scripts before services. Initialization installs the atomic fail-closed firewall, generates configuration and creates mutable paths before engines start. Local applications do not wait for a working tunnel. WireGuard setup and firewall maintenance remain privileged. Only the short-lived endpoint DNS resolver uses the existing nobody identity (UID/GID 65534), restricting the bootstrap DNS exception to its sockets; applications retain VPN DNS and cannot use LAN DNS when the tunnel is down. Private networks directly connected to the container are detected automatically, including local HAOS services. Additional LAN exceptions come from `lan_networks`. Dedicated TCP source-port routing keeps published-interface replies on the original container interface; the firewall still rejects new unapproved outbound connections, even with a published source port. DNS filtering precedes both automatic and explicit local-network exceptions.

Ingress on port 8099 provides setup, live status and diagnostics. Seerr is published on 5055 and Prowlarr on 9696. Advanced application interfaces require the corresponding Home Assistant option and authenticated Ingress. Diagnostics are available independently; explicit searches contact sources and show real Arr decisions. Media servers are optional and separate. The overview reports active torrents, monitored titles, enabled-source availability and open requests from a shared read-only observation cache. Failed application reads retain timestamped last known values. The Requests table explains native Arr queues, missing monitored media and torrents outside Arr queues. Explicit Inspect releases actions contact sources without grabbing releases. Contextual connection checks replace the Setup tab; bundled application versions are on Overview. Config saves validated seeding, concurrency and dual-audio preferences in `/data/pompey/state/preferences.json` under the stack lock. All policy consumers read these effective preferences, with legacy HA/environment values used until the first save. The configuration job applies live qBittorrent preferences and resynchronizes Recyclarr when the audio preference changes; only a successful complete pass acknowledges them in `preferences-applied.json`. Controller failures leave them visibly pending. Storage warnings remain visible across tabs. Arrow keys, Home and End switch tabs.

The controller serializes mutations. Download maintenance, rating routing, profiles and initialized search connections have their own prerequisites. Before Seerr has its first administrator, its public wizard is available and API-key 403 responses are expected. Afterwards both Arr connections, configured Prowlarr apps and an enabled synchronized source are required. Optional sign-in and interface settings do not override required connection failures.

Cold HA backups stop the add-on for a consistent state copy. There is no runtime bundle updater, database rollback manager or supported migration from the old architecture. Fresh installations remain the primary supported layout. Release acceptance additionally exercises a selected previous stable image with real completed, waiting and partial-download state; arbitrary historical migrations and downgrades remain unsupported. See [testing](../docs/testing.md) for what automated acceptance proves and the remaining hardware boundaries.

## Download and storage safety

qBittorrent excludes executable/script filenames (`exe`, `com`, `scr`, `msi`, `bat`, `cmd`, `ps1`, `vbs`, `js`, `lnk`) with its native case-insensitive file filter. The filter applies after torrent metadata is known and before those files are selected for transfer. Pompey cannot identify every unsafe release from a search title and does not scan media for malware. Mixed wanted/excluded files may share torrent pieces.

After a recovered VPN interface replacement, Pompey gracefully restarts qBittorrent once to reopen bound connections. Native resume data preserves partial bytes and individual stopped torrents; deliberately held services are not restarted.

Startup remembers paths previously observed on network filesystems and refuses a later local-filesystem fallback. During operation, a bounded storage check every fifteen seconds verifies mount identity and write operations. Detected loss/read-only/full/permission failures stop qBittorrent, Radarr and Sonarr while leaving local requests and setup accessible. The dashboard retains the overview and explains the storage interruption. Restored storage releases only the applications Pompey held. Detection is periodic, not an atomic safeguard against every write during a mount outage. Native cleanup interrupted mid-removal can leave files requiring review; Pompey does not guess which unowned files to delete.

Home Assistant Logs retain the first actionable upstream warning/error and summarize equivalent repeats for sixty seconds. Redaction is best effort; review copied logs before posting them publicly. Diagnostic uploads are not automated.
